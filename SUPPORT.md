# Support

Use the channel that matches your request so it reaches the right workflow.

## Bugs

Open a **Bug report** from the repository’s Issues page and include reproducible steps, environment information, and screenshots/logs when useful.

https://github.com/zexy2/postify/issues/new/choose

## Feature requests

Use the **Feature request** issue form. Describe the user problem first, then the smallest useful solution and how success should be measured.

https://github.com/zexy2/postify/issues/new/choose

## Security vulnerabilities

Do **not** open a public issue with vulnerability details. Use GitHub private vulnerability reporting from the repository Security tab and follow [SECURITY.md](SECURITY.md).

https://github.com/zexy2/postify/security

## Questions and open-ended ideas

For implementation questions, contribution help, or ideas that are not yet scoped work, use [GitHub Discussions](https://github.com/zexy2/postify/discussions). Start with [CONTRIBUTING.md](CONTRIBUTING.md) for the local workflow.

Use Issues when the conversation has become a reproducible bug or a concrete, actionable feature request.

## Production

Current production application:

https://postify.zekiakgul.dev/

Postify is an open-source project and does not currently promise a commercial support SLA. Reports that include clear reproduction evidence are much easier to investigate.
