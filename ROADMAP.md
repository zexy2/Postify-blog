# Postify Roadmap

Postify is evolving as a **Verified Knowledge** network: practical technical knowledge with explicit evidence, reproducibility, freshness, and community validation.

This roadmap communicates product direction, not guaranteed delivery dates. Concrete implementation work should be tracked in GitHub Issues; open-ended ideas and questions belong in GitHub Discussions.

## Now

- Strengthen the verification and freshness contract without overstating trust.
- Keep discovery, reading, and authoring flows accessible, fast, and understandable on desktop and mobile.
- Harden authentication, abuse resistance, data boundaries, and release security.
- Keep CI/CD, database/RLS verification, browser coverage, and production exact-SHA checks release-blocking.
- Make contributor and maintainer workflows easier to understand and reproduce.

## Next

- Expand verification beyond the current deterministic Node.js foundation while preserving strict safety boundaries.
- Improve evidence invalidation when tracked runtimes, packages, or source assumptions change.
- Make provenance, revision history, and canonical-source relationships more useful to readers.
- Improve community evidence so “worked / didn’t work” signals are informative without becoming popularity metrics.
- Make knowledge gaps and saved intent more useful across authenticated sessions.

## Later

- Explore isolated verification runtimes for additional rule-safe verification types.
- Expand machine-readable Verified Knowledge integrations where the trust model can remain explicit.
- Improve contributor-facing tooling around verification recipes, evidence quality, and maintenance ownership.
- Explore broader community and organization workflows only when the core Verified Knowledge experience proves the need.

## How to participate

- **Reproducible bug:** use the repository Bug Report issue form.
- **Scoped feature work:** use the Feature Request issue form.
- **Open-ended idea or product question:** start a [GitHub Discussion](https://github.com/zexy2/postify/discussions).
- **Security vulnerability:** use [private vulnerability reporting](https://github.com/zexy2/postify/security/advisories/new).

See [CONTRIBUTING.md](CONTRIBUTING.md) for the contribution workflow and [SUPPORT.md](SUPPORT.md) for the right support channel.
